En Español Validator Help

Validation guide for the Nationwide Spanish‑language page checker and report generator.

Setup

Prerequisites & Installation

Before you begin, ensure you have:

  • Node.js (version 14 or later) installed.
  • npm (comes with Node.js) – used to install dependencies.
  • A terminal / command prompt to run the script.

Install dependencies

Navigate to the project directory and run:

npm install playwright exceljs csv-parse franc

Playwright will download the required browser binaries during installation. This step may take a few minutes.

Note: The script assumes that the core library files (espanol-validator-core.js) are located in a lib/ folder relative to the runner. If you have a different structure, adjust the require paths accordingly.

Overview

What this tool does

This validator checks whether a page or a list of pages contains a valid Spanish-language experience. It detects whether a page has an En Español language switch link, follows that link, and validates the resulting page content exactly at the URL reached. It then produces JSON, HTML, and Excel reports.

The implementation in Updated_espanol-validator-runner.js is designed to handle real-world scenarios such as direct Spanish URLs, unavailable pages, missing language links, and cookie banners.

This version uses a strict validation policy: a page is only marked PASS if the exact target page (the one reached via the “En Español” link) itself is properly translated. No fallback or override is applied.

Core functionality

Key features

  • Reads URLs from a CSV file or accepts a direct URL argument.
  • Detects direct Spanish URLs such as espanol.nationwide.com and /es/ or /espanol/ paths.
  • Finds an En Español link using text, hreflang, lang attributes, and fallback heuristics.
  • Identifies if the current page is already Spanish using HTML language metadata, language detection, and keyword checks.
  • Skips pages that are unavailable or display error templates such as Application Unavailable.
  • Validates translated content using Spanish stopwords, keywords, and language detection.
  • Creates reports in JSON, HTML, and Excel formats.
  • Supports cookie banner dismissal for common site patterns.
How it works

Validation flow

  1. Read the target URL(s) from the command line or the default url.csv file.
  2. Open the page in headless Playwright.
  3. Check whether the page is unavailable or is a known error page.
  4. Look for an En Español link or other language-switch indicator.
  5. If the current page is already Spanish, validate it directly.
  6. If a switch link exists, click it and validate the resulting page.
  7. No fallback step: the page reached via the link must validate as Spanish, otherwise the test is marked FAIL.
  8. Save the generated result summary and reports.
Validation engine

How the script decides PASS / FAIL / SKIP

The validation logic follows a deterministic decision tree. Each page is evaluated as follows:

  1. Unavailable check – if the HTTP status is 4xx/5xx or the page contains “application unavailable” text, the test is SKIPPED (to avoid false negatives).
  2. Direct Spanish detection – if the URL itself indicates Spanish (espanol host, /es/ path, or lang=es query param), the page is assumed to be Spanish and validated immediately.
  3. “En Español” link search – the script looks for a clickable link using multiple selectors and text patterns. If none is found:
    • If the current page is already Spanish (detected via <html lang="es"> or language detection), it is validated directly.
    • Otherwise, the test is SKIPPED with a note that no switch link exists.
  4. Click & validate – the link is clicked, and the resulting page is checked for Spanish content using:
    • Presence of <html lang="es">
    • Language detection via the franc library on the page body (first 1000 characters)
    • Keyword heuristics (fallback) – common Spanish terms like “seguro”, “servicios”, “contacto”, etc.
  5. Final status – if Spanish is confirmed, the test is PASS; otherwise, it is FAIL with appropriate error details.

Note: The script uses a combination of signals to reduce false positives. The keyword list is intentionally small to avoid matching common English words that appear in Spanish contexts.

Usage

Run the validator

Single URL

node Updated_espanol-validator-runner.js "https://www.nationwide.com/"

CSV file default

node Updated_espanol-validator-runner.js

If no URL argument is provided, the script checks for a default file named url.csv in the project root. If the CSV exists, it reads URLs from it. If not, it falls back to a default page such as https://www.nationwide.com/.

CSV format

File format for url.csv

The CSV is expected to be a simple list of URLs, ideally with a header named url.

url
https://www.nationwide.com/
https://www.nationwide.com/agents/
https://espanol.nationwide.com/personal/insurance/life/permanent/whole/

The script handles quoted entries and multi-column CSV files by looking for a column named url or falling back to the first column when needed.

Validation logic

What counts as Spanish?

The validator uses a layered approach to determine whether a page is Spanish:

  • Direct URL detection: URLs with espanol in the host or /es/, /espanol/, or lang=es patterns.
  • HTML metadata: lang="es" or similar Spanish language attributes.
  • Language detection: the franc library checks the page body text.
  • Keyword heuristics: common Spanish terms such as seguro, servicios, contacto, privacidad, vida, and español.

If Spanish is detected, the script validates the page. Otherwise, it marks the page as FAIL (or SKIPPED if no link was found).

Status values

Result states

PASS
The “En Español” link led to a page that is itself fully translated into Spanish.
FAIL
The page was reachable but did not validate as Spanish content.
SKIPPED
The page was unavailable, had no usable language-switch link, or was not testable.

The script also reports Application Unavailable pages as skipped, which prevents a site outage from being counted as a real translation failure.

Validation details

Important validation rules

  • If the site returns an unavailable page template, the validator skips it with a skip status.
  • If no En Español link exists but the page itself is already Spanish, it validates the current page directly.
  • If a link is present and clickable, the validator opens the Spanish page and validates it.
  • Page navigation errors, click failures, and unexpected exceptions are reported as FAIL with context in the error message.
  • Page Error tracking: when an En Español link exists and errors occur during click or page load, the error is captured in the "Page Error" column for root cause analysis.
  • No fallback override: the page reached via the link is the only page evaluated for PASS/FAIL.
Output reports

Generated files

After execution, the script writes reports into the reports folder.

  • JSON: includes the validation summary and raw result objects with all validation fields.
  • HTML: a human-readable table with URL, link status, translation result, status, page error (if any), and validation details.
  • Excel: workbook with the same result set for spreadsheet review.

Report columns

  • URL: the target page URL
  • En Español Element: Yes/No – whether an En Español link was detected
  • En Español Link: the href of the Spanish version (if found)
  • Spanish Translate: Yes/No – whether Spanish content was validated
  • Status: PASS, FAIL, or SKIPPED
  • Detection Method: which signal triggered Spanish detection (url, html-lang, hreflang, og-locale, franc, keyword, none)
  • Page Error: error message if click or page load failed during Spanish page navigation
  • Validation Details: full error or success message

Summary values include:

{
  "total": 4,
  "pass": 1,
  "fail": 2,
  "skip": 1,
  "unavailable": 1
}
Troubleshooting

Common issues and fixes

  • Page is marked SKIPPED: the target page is unavailable or not testable at the moment.
  • Page is marked FAIL: the page loaded but no Spanish content or language indicators were detected. Check the "Validation Details" column for specifics.
  • Page Error column shows "Click failed": the En Español link exists but could not be clicked. See the error message for details. This typically indicates a page structure issue or timing problem.
  • Page Error column shows "Page load error": the Spanish page failed to load after clicking the link. Check the "Validation Details" column for the specific error.
  • No En Español link found: the page may already be Spanish, or the site structure may not include a visible language switch.
  • Cookie banner blocks interaction: the validator attempts a standard banner dismissal but some sites may still require custom selectors.
  • CSV read issue: ensure the file contains a valid url header or a clean first-column list of URLs.
Project notes

Important implementation notes

This script relies on Playwright for browser automation, csv-parse/sync for CSV parsing, and franc for language detection. It is designed to preserve a practical balance between heuristic detection and real page validation.

The most robust behavior is to separate unavailable pages from genuine page failures. That avoids false negatives when a target site is temporarily down but still maintains strict validation of real Spanish content.

Strict mode: no fallback is applied. A PASS means the exact linked page is translated. This satisfies mission‑critical validation where every specific URL must work.

Page Error tracking: when an En Español link is found and detected, any errors during navigation (click failure or page load timeout) are captured in the report for detailed root cause analysis. This helps distinguish between translation issues and technical problems.

Report format: all reports (JSON, HTML, Excel) include the Page Error field, enabling consistent error tracking across different report formats for stakeholder review and debugging.
