📌 1. Overview & Purpose

The NW Interstellar Angular NF API Testing Framework is a complete enterprise automated testing tool designed to validate Nationwide Mutual Insurance / Financial Services Angular Nationwide Funds (NF) API endpoints.

It leverages Newman (Postman CLI runner) orchestrated via Node.js and PowerShell scripts to run multiple collection test suites against distinct API environments (prod, dev, internal), perform detailed assertions for data integrity, generate structured reports (HTML, JSON, XLSX, JUnit XML), and automatically deliver execution results via SMTP email.

⚡ Automated Runner

Executes Postman collections iteratively using CSV ticker lists (e.g., fund tickers like AAF, GIF, etc.).

📊 Multi-Format Reporting

Generates interactive HTML Extra reports, raw JSON execution states, Excel summary matrices, and JUnit XML.

📬 Instant Notifications

Integrated SMTP relay automatically attaches HTML and XLSX reports to email recipients post-execution.

⚙️ 2. Installation & Prerequisites

Follow these step-by-step instructions to set up the execution environment on a new machine or server.

Prerequisites Checklist

  • Operating System: Windows 10 / Windows Server 2016+ (or macOS/Linux with PowerShell core).
  • Node.js Runtime: Version 16.x or higher (Download from nodejs.org).
  • PowerShell: Version 5.1 or PowerShell Core 7+.
  • Git / Access: Workspace repository cloned locally.

Step 1: Verify Node.js and NPM

Open Terminal / PowerShell and run:

node --version
npm --version

Step 2: Install Project Dependencies

Navigate to the project root folder and execute npm install to install all required packages:

cd C:\NW_Testing\NW_Interstellar_Angular_NF_API_Testing
npm install
Package Manifest Details:

The installation pulls the following key libraries from package.json:

  • newman (^6.1.3) - Postman CLI runner engine
  • newman-reporter-htmlextra (^1.23.1) - Interactive dark/light HTML report dashboard generator
  • xlsx (^0.18.5) - Excel workbook generation for test result metrics
  • nodemailer (^6.10.1) - SMTP email delivery engine
  • dotenv (^17.4.2) - Environment file secrets manager

Step 3: Set PowerShell Execution Policy

If executing PowerShell scripts, ensure script execution is permitted for your user session:

Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser

🔄 4. Architecture & Workflow

The framework follows an end-to-end automated pipeline lifecycle from trigger invocation down to report generation and email notification:

1

Trigger Invocation

Task Scheduler / Manual CLI triggers run-fund-profile-api.bat or node scripts/run-collection.js.

2

Configuration & Environment Initialization

Parameters are resolved from CLI flags or .env file (e.g. --env, --data ticker.csv, --smtp-enabled).

3

Postman Collection Execution (Newman)

Newman executes requests against Nationwide API endpoints (e.g. /funds-and-assets-management/fund-profile/v1/funds/{ticker}) iterating over each row in ticker.csv.

4

Assertions & Data Quality Validation

Validates Status Code 200, JSON Schema compliance, mandatory data element, null/empty checks, SLA response times (< 3000ms), and auth token exchanges.

5

Multi-Format Report Generation

Generates newman-report-latest.html, raw JSON summaries, JUnit XML, and invokes generate-xlsx-report.js to output a comprehensive Excel spreadsheet.

6

SMTP Email Dispatch & Cleanup

Invokes post-run-actions.ps1 or nodemailer to send an email summary with HTML & XLSX reports attached to configured stakeholders.

🧠 5. How It Works

1. Data Iteration via CSV Tickers

When running fund profile collections, Newman uses ticker.csv (or tickers/all_tickers.csv) as an iteration data source. Each line contains a ticker identifier (e.g., AAF, GIF, NWX). Newman injects the variable into path variables like {{ticker}} for each iteration.

2. OAuth / Morningstar Access Code Pre-Request Script

For endpoints requiring authorization (such as Pricing and Performance), the Postman collection contains a pre-request script that executes an initial OAuth/Auth token exchange call to obtain a temporary access token before sending the target API request.

3. Multi-Environment Switching

The framework seamlessly targets different target environments via Postman environment files or config.json:

Environment Key Base URL Default Headers / Auth
prod https://api.nationwide.com client_id, X-NW-Message-ID
dev https://api-test.nwie.net Dev client credentials & test headers
internal https://api-int.nwie.net Internal network routing headers

4. Response Body State Detection

The reporting engine in generate-xlsx-report.js parses response bodies and detects specific data states:

  • Valid Data - Response body parsed successfully with non-null data content.
  • Empty / Null Data - Valid HTTP 200 response, but data: null or empty array detected.
  • Error / Fault - HTTP 4xx/5xx status code or invalid JSON fault response.

✅ 7. Validations & SLA Checks

The collections incorporate robust Postman tests to ensure API reliability, structural compliance, and performance SLA standard adherence:

// Sample Postman Test Suite in Collections
pm.test("Status code is 200 OK", function () {
    pm.response.to.have.status(200);
});

pm.test("Response time is within SLA (< 3000ms)", function () {
    pm.expect(pm.response.responseTime).to.be.below(3000);
});

pm.test("Response contains required 'data' property", function () {
    var jsonData = pm.response.json();
    pm.expect(jsonData).to.have.property('data');
    pm.expect(jsonData.data).to.not.be.null;
});

pm.test("Content-Type header is JSON", function () {
    pm.response.to.have.header("Content-Type");
    pm.expect(pm.response.headers.get("Content-Type")).to.include("application/json");
});
Validation Matrix Overview:

If any test assertion fails (e.g., HTTP 500 error or response time > 3000ms), Newman records a failure assertion, sets a non-zero exit code, and flags the failure in both HTML and Excel report outputs.

🚀 8. Execution Options & CLI Help

Standard NPM Commands

# Default collection run via run-collection.js
npm run api:run

# Specific Fund Profile collection execution with default CSV
npm run api:run:fund-profile

Node.js Direct CLI Arguments

You can pass custom arguments to scripts/run-collection.js:

node scripts/run-collection.js \
  --collection collections/fund-profile-api.postman_collection.json \
  --env environments/fund-profile-api.postman_environment.json \
  --data ticker.csv \
  --insecure true \
  --smtp-enabled true \
  --smtp-host mail-gw.ent.nwie.net \
  --smtp-to gunasb@nationwide.com
Flag / Parameter Type Description & Default
--collection String Path to Postman collection JSON file.
--env String Path to Postman environment JSON file.
--data String Path to iteration data CSV or JSON file (e.g. ticker.csv).
--insecure Boolean Bypasses SSL/TLS certificate verification when true.
--smtp-enabled Boolean Enables SMTP email sending post-run (Default: false).
--smtp-host String SMTP relay server hostname (e.g. mail-gw.ent.nwie.net).
--smtp-to String Recipient email address(es), separated by comma or semicolon.

Alternative Dynamic Runner (NW_Interstellar_Angular_NF_API_Testing_new)

# Run against production
node runTests.js --env prod

# Run against dev or internal
node runTests.js --env dev
node runTests.js --env internal

# Execute Windows Batch script for all environments
run-all-envs.bat

➕ 9. How to Add New Collections in the Future

When new Nationwide API endpoints or fund features are developed, follow this step-by-step guide to add and integrate a new Postman collection into the framework:

Step 1: Export Postman Collection File

  1. Open Postman and locate your new API collection.
  2. Right-click the collection name → click Export.
  3. Select Collection v2.1 (recommended) format.
  4. Save the .json file into the project's collections/ directory (e.g. collections/new-fund-feature.postman_collection.json).

Step 2: Ensure Path Variable Standardization

Make sure requests in the Postman collection use parameterized URL variables matching your ticker data CSV/JSON fields:

  • For path variables: https://{{baseUrl}}/funds-and-assets-management/fund-profile/v1/funds/{{fundCode}}/new-feature or {{ticker}}
  • For standard headers: Include client_id and X-NW-Message-ID header variables.

Step 3: Integrate and Run the New Collection

Depending on which runner mode you use, follow the corresponding method below:

Method A: Direct Script & NPM Script Execution

Execute the new collection individually using run-collection.js:

node scripts/run-collection.js \
  --collection collections/new-fund-feature.postman_collection.json \
  --env environments/fund-profile-api.postman_environment.json \
  --data ticker.csv \
  --insecure true

Optionally add a shortcut to package.json under "scripts":

"scripts": {
  "api:run:new-feature": "node scripts/run-collection.js --collection collections/new-fund-feature.postman_collection.json --env environments/fund-profile-api.postman_environment.json --data ticker.csv --insecure true"
}

Method B: Add to Config-Driven Runner (NW_Interstellar_Angular_NF_API_Testing_new/config.json)

Open config.json and append your new endpoint definition to the "collections" array:

{
  "name": "New Fund Feature",
  "endpoint": "/funds-and-assets-management/fund-profile/v1/funds/{ticker}/new-feature",
  "method": "GET",
  "tickerFile": "tickers/all_tickers.csv",
  "validationRules": {
    "expectedStatus": 200,
    "requiredFields": ["data"],
    "checkEmptyData": false
  }
}

Run via node runTests.js --env prod.

Method C: Include in Automated Scheduled Batch Runs

If using the scheduled batch runner (`run-fund-profile-api.bat`), open `scripts/run-all-collections-scheduled.ps1` and add the new collection JSON file path to the collection execution loop array so it executes automatically during scheduled jobs.

Report Verification:

Once executed, verify that results for your new collection appear in reports/newman-report-latest.html and reports/newman-summary-latest.xlsx.

⏰ 12. Windows Task Scheduler Setup

Option 1: Using Windows GUI

  1. Press Win + R, type taskschd.msc, and press Enter.
  2. In the right pane, click Create Task...
  3. General Tab: Name the task Angular_NF_API_Testing - Fund Profile API and check "Run with highest privileges".
  4. Triggers Tab: Click New... → Set schedule (e.g. Daily at 2:00 AM or Weekly on Mondays).
  5. Actions Tab: Click New... →
    • Program/script: C:\NW_Testing\NW_Interstellar_Angular_NF_API_Testing\run-fund-profile-api.bat
    • Start in: C:\NW_Testing\NW_Interstellar_Angular_NF_API_Testing
  6. Click OK and enter Windows credentials if prompted.

Option 2: Using Automated PowerShell Script

Open PowerShell as Administrator and execute:

$TaskName = "Angular_NF_API_Testing - Fund Profile API"
$BatchPath = "C:\NW_Testing\NW_Interstellar_Angular_NF_API_Testing\run-fund-profile-api.bat"
$WorkDir   = "C:\NW_Testing\NW_Interstellar_Angular_NF_API_Testing"

# Trigger: Daily at 2:00 AM
$Trigger = New-ScheduledTaskTrigger -Daily -At 2:00AM

# Action & Settings
$Action = New-ScheduledTaskAction -Execute $BatchPath -WorkingDirectory $WorkDir
$Settings = New-ScheduledTaskSettingsSet -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -StartWhenAvailable

Register-ScheduledTask -TaskName $TaskName -Trigger $Trigger -Action $Action -Settings $Settings -RunLevel Highest
Write-Host "✓ Scheduled Task Registered Successfully!"

🔍 13. Troubleshooting & FAQ

❓ 'node' or 'newman' is not recognized as an internal or external command ▼

Cause: Node.js is not installed or the executable path is missing from your system PATH variable.

Fix: Install Node.js v16+ from nodejs.org, restart your terminal session, and verify with node -v.

❓ SSL Certificate Verification Errors (DEPTH_ZERO_SELF_SIGNED_CERT) ▼

Cause: Corporate SSL proxies/firewalls intercepting HTTPS requests.

Fix: Pass the --insecure true flag to run-collection.js or set NODE_TLS_REJECT_UNAUTHORIZED=0 in your environment.

❓ SMTP Mail Fails to Send (Connection Timeout / ECONNREFUSED) ▼

Cause: Incorrect SMTP host or firewall blocking port 25/587.

Fix: Verify SMTP_HOST=mail-gw.ent.nwie.net when inside Nationwide corporate network. Ensure port 25 is accessible via Test-NetConnection mail-gw.ent.nwie.net -Port 25 in PowerShell.

❓ PowerShell Script Execution Blocked ("cannot be loaded because running scripts is disabled") ▼

Cause: Restricted PowerShell execution policy.

Fix: Run Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser in PowerShell.
