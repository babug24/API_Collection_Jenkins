1. Overview & Purpose

The Spanish Language Conversion Validator (validate1.js) is an enterprise-grade automated testing script engineered to verify that web pages correctly convert from English to authentic Spanish content when users click the "En Español" language switcher.

🔍 The Problem It Solves

Standard link-checker scripts only check if the URL changes to a Spanish host (e.g. espanol.nationwide.com). However, websites frequently redirect to Spanish domains while still rendering untranslated English text, creating false positive QA passes.

💡 The Solution

This script inspects the rendered DOM content using four independent validation signals (HTML tags, OpenGraph locale, statistical language AI, and dictionary word boundaries) to produce defensible QA sign-off evidence.

Key Capability: Analytics URL Sanitization

Google Analytics tracking parameters (such as ?_gl=... or ?_gcl=...) appended during link navigation can trigger Angular/React fallback behavior to English. The validator detects these parameters and automatically navigates to clean URLs to ensure accurate, zero-false-negative testing.

2. System Architecture & Workflow Flow

The validator follows a strict, resilient execution pipeline for every input URL:

1
Input Parsing

Reads target URLs from CLI arguments or batch CSV files (e.g. urls.csv, Full_Production_url.csv).

2
Chrome Launch & CDP Cache Clear

Launches headless Chrome with anti-crash flags and clears browser cache via Chrome DevTools Protocol (CDP).

3
English Page Load & Link Discovery

Navigates to the page and locates the "En Español" or "Español" link in headers, footers, or the full DOM.

4
Click Execution & URL Sanitization

Clicks the link, waits for SPA or page navigation, and strips any trailing analytics parameters (?_gl=...).

5
Lazy-Scroll & Text Extraction

Waits for single-page app root (app-root), triggers virtual scroll, and extracts main content text samples.

6
Layered 4-Signal Analysis

Evaluates HTML lang, og:locale, statistical trigram analysis (franc), and dictionary matches.

7
Incremental Excel Auto-Save

Appends result and updates timestamped Excel report in reports/ every 5 URLs to protect progress.

3. Layered Validation Methodology (The 4 Signals)

Rather than relying on a single metadata check, every page undergoes multi-factor verification:

Signal # Name Check Type Pass Criteria
Signal 1 HTML Lang Attribute DOM Property <html lang="es"> or lang="es-US" (Regex: /^es(-\w+)?$/i)
Signal 2 OG Locale Meta Tag Meta Property <meta property="og:locale" content="es_US"> (Non-penalizing if absent)
Signal 3 Content Detection (franc AI) Trigram Analysis Top detected language is Spanish (spa) with confidence score ≥ 90%
Signal 4 Keyword Scanning Dictionary Scan Word-boundary safe match against 50+ distinctive Spanish insurance terms

Scoring & Threshold Rules

A page achieves an overall PASS if:

  • At least 1 distinctive Spanish keyword is detected in extracted body samples, OR
  • The multi-signal confidence score reaches or exceeds 75% across all applicable signals.

4. Installation & Setup Guide

Prerequisites

  • Operating System: Windows 10/11, macOS, or Linux.
  • Node.js: Node.js v16.0.0 or higher (v18+ recommended).

Installation Steps

Open your PowerShell or terminal in the project directory and run:

# 1. Clone or navigate to project directory
cd C:\NW_Testing\NW_spanish_validation

# 2. Install all required dependencies
npm install

Required Packages

Package Version Role in Script
puppeteer ^25.7.0 Headless Chrome browser automation and DOM manipulation.
xlsx ^0.18.5 Generates formatted Excel reports (.xlsx) with worksheets.
franc ^6.2.0 Trigram statistical language detection (loaded dynamically via ESM import).
csv-writer ^1.6.0 CSV utility helper for data exporting.

5. Execution & Usage Guide

1. Single or Multiple URLs

Pass URLs directly via command line arguments.

2. Batch File (CSV or Text)

Use the --file flag with any CSV containing a url column.

3. Debug Mode

Add --debug to run browser visibly with slow-motion animation.

Command Examples

# Run validation on a single URL
node validate1.js https://www.nationwide.com/

# Run validation on a CSV file
node validate1.js --file urls.csv

# Run validation on full production batch CSV
node validate1.js --file Full_Production_url.csv

# Run in DEBUG mode (visible browser window for inspection)
node validate1.js --file urls.csv --debug

6. Report Structure & Result Interpretation

Reports are auto-saved in the reports/ folder with timestamped filenames:
reports/spanish_conversion_report_YYYY-MM-DD_HH-MM-SS.xlsx

Excel Report Columns Breakdown

Column Name Description & Example Values
URL The requested English page URL tested.
En Español Element Found, Not Found, or N/A (if URL was already Spanish).
En Español Link The target href found on the page or Valid / Invalid state.
Spanish Translate Pass or Fail language translation indicator.
Status Overall status: PASS or FAIL.
Page Error HTTP status error (e.g. HTTP 404) or N/A.
Validation Details Explicit explanation (e.g. "Target page content remains in English (Spanish translation missing on page).")

7. Troubleshooting & Anti-Crash Safety

1. Windows Temp File Lock (Error EBUSY)

Issue: Windows locks Chrome profile temporary metric files on browser exit.
Solution Included: 25+ Puppeteer launch flags (e.g., --disable-background-networking, --disable-breakpad) and a try-catch block around browser.close() completely suppress this Windows OS locking behavior.

2. Detached Frame Errors during SPA Redirects

Issue: Occurs if an Angular/React client-side redirect reloads the DOM during extraction.
Solution Included: Safe try-catch wrappers around scrolling and DOM evaluation with fallback raw text extraction prevent frame detachment from halting execution.

3. Large Production Batch CSV Runs (>800 URLs)

Feature: Progress is automatically written to the Excel file every 5 URLs. If a machine reboots or network drops, all processed URLs are already saved in the report.
